# WallHub v2.0.2

## 中文更新

### 新功能

- 新增内置更新中心，可在设置中查看当前版本、检查 GitHub Release、下载并安装经过 SHA-256 校验的更新；默认只提示，用户明确开启后才会自动更新。
- 新增 Windows 安装版、便携版和跨平台源码部署的外部更新器，并为 Docker 提供 amd64/arm64 GHCR 镜像及可选的 Watchtower 自动更新 profile。

### 优化

- 更新只会在下载、MPKG 转换、Steam 登录和文件传输均空闲时安装，并通过 staging、事务 journal、连续健康检查和启动恢复降低更新中断风险。
- Windows Launcher 会等待相关进程安全退出后再覆盖文件；源码模式会安装生产依赖，并继承 WallHub 中配置的网络代理。
- Docker 自动更新仅选择带 WallHub scope 和 enable label 的目标容器，并保留当前已生效的端口、环境变量、volume、restart policy、labels、hostname 和启动命令。
- 新增已安装文件 manifest，可在后续升级中清理已从新版移除的程序文件，同时保留用户数据和未知本地文件。

### 修复

- 修复更新 helper 并发运行时可能争用 staging、备份和事务文件的问题，并支持崩溃后恢复陈旧锁。
- 修复无 Origin 的局域网请求可远程触发更新操作的问题；非浏览器更新请求现在仅允许来自本机回环地址。
- 修复 Windows 构建上下文中的 CRLF 行尾导致 Docker entrypoint 无法启动，以及新 Docker volume 子目录归属 root 导致 SteamKit 初始化失败的问题。
- 修复 Windows 便携更新包额外嵌套目录、Launcher 进程交接和失败更新回滚中的稳定性问题。

## English Release Notes

### Features

- Added a built-in update center for viewing the current version, checking GitHub Releases, downloading updates, and installing packages verified with SHA-256. Updates are notification-only by default and become automatic only after explicit opt-in.
- Added an external updater for Windows installer, portable, and cross-platform source deployments, plus amd64/arm64 GHCR images and an optional Watchtower auto-update profile for Docker.

### Improvements

- Updates install only while downloads, MPKG conversions, Steam sign-ins, and file transfers are idle. Staging, a transaction journal, consecutive health checks, and startup recovery reduce interruption risk.
- The Windows Launcher waits for related processes to exit before replacing files. Source updates install production dependencies and inherit the network proxy configured in WallHub.
- Docker auto-update targets only the container selected by the WallHub scope and enable label, while preserving its active ports, environment variables, volumes, restart policy, labels, hostname, and command.
- Added an installed-files manifest so later upgrades can remove program files deleted by a new version without deleting user data or unknown local files.

### Fixes

- Fixed concurrent update helpers competing for staging, backup, and transaction files, with stale-lock recovery after a crashed helper.
- Fixed update mutations without an Origin header being remotely triggerable from the local network. Non-browser update requests are now restricted to loopback clients.
- Fixed Docker startup failures caused by CRLF entrypoint line endings from Windows build contexts, and SteamKit permission failures caused by root-owned subdirectories in a new Docker volume.
- Fixed stability issues involving an extra directory level in Windows portable update packages, Launcher process handoff, and failed-update rollback.
